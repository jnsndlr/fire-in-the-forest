# Working on Fire in the Forest

Read `README.md` before making changes. It is the source of truth for the current project goals, design direction, prototype scope, controls, and validation commands.

This is an initial get-off-the-ground prototype. Its design and architecture are provisional and may change through playtesting and user feedback. Follow the user's latest direction over older design notes; do not treat prototype values or the original specification as fixed requirements.

- Build for Godot 4 with GDScript. The current scene uses 3D assets and physics with movement constrained to a side-view plane.
- Prioritize responsive traversal, readable landing surfaces, fair pressure, and quick retries. Preserve the intended poignant, welcoming tone.
- Keep the README current when behavior, controls, scope, or project direction changes. Distinguish implemented features from goals and proposals.
- Use simple geometry and painterly materials as the starting art approach. Keep the squirrel and traversal routes legible in motion.
- For gameplay changes, run the relevant Godot checks documented in the README. For rendering or camera changes, also inspect a rendered scene. Do not claim visual validation from headless checks alone.
- Keep additions proportional to the prototype. Introduce more architecture when a concrete need warrants it.
